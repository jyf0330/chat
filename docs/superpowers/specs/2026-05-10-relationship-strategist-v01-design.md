# 恋爱/暧昧关系策略师 v0.1 设计规格

## 1. 产品定位

关系策略师 v0.1 是一个面向恋爱/暧昧聊天场景的沟通辅助系统。它不只是生成 5 条回复，而是先判断关系阶段、对方情绪、当前风险和下一步策略，再给出可复制的话术。

默认方案：自由策略师 + 底线拦截。

产品目标：
- 帮用户处理“对方刚发来一句难回的话”的即时回复场景。
- 输出稳妥克制、能解释情绪信号的策略建议。
- 在允许自然升温和有效推进的同时，拦截骚扰、操控、PUA、越界施压等方向。
- 让用户看到“为什么这么回”，而不是只拿到一句话术。

非目标：
- 不做心理诊断。
- 不断言对方真实想法。
- 不承诺某句话一定能挽回、升温或成交。
- 不鼓励用户绕过对方明确边界。

## 2. 默认使用场景

主场景：

用户复制或输入对方刚发来的消息，并可附带最近 3-10 条聊天上下文。系统结合对象档案，输出局势判断和回复策略。

默认输入：

```json
{
  "latest_message": "最近真的有点累，改天再说吧。",
  "recent_context": [
    {"speaker": "user", "text": "那今晚还聊吗？"},
    {"speaker": "target", "text": "最近真的有点累，改天再说吧。"}
  ],
  "profile": {
    "name": "小林",
    "relationship_stage": "暧昧初期",
    "user_goal": "稳定升温",
    "reply_style": "回复偏慢，表达克制",
    "likes": ["轻松聊天", "电影", "不被追问"],
    "dislikes": ["连续追问", "强迫解释", "过度暧昧"],
    "recent_state": "最近工作累，互动变少",
    "successful_patterns": ["先接情绪，再轻轻留连接"]
  },
  "user_intent": "我想回得体贴一点，同时不要显得卑微"
}
```

## 3. 用户可见输出

v0.1 输出完整策略，不只输出话术。

```text
关系阶段：暧昧初期，置信度中等
对方情绪：偏疲惫，像是在暂时撤退，不是明确拒绝
策略判断：现在不适合追问，适合先降压、接住情绪、保留连接

首推回复：
那你先好好休息，别硬撑。等你缓过来我们再聊，我不催你。

备选回复：
1. 更轻松：收到，那今天先放过你。记得早点休息，我晚点不吵你。
2. 更克制：好，那你先休息，等你状态好点再说。
3. 更温柔：辛苦了，先把自己照顾好。聊天不急，我在。

风险提醒：
不要追问“你怎么又累了”或表达委屈，这会增加对方压力。

下一步：
今晚不要连续补消息。明天中午可以发一个低负担问候。
```

## 4. 关系阶段体系

v0.1 使用 7 个阶段，足够覆盖主要策略差异。

| 阶段 | 判断信号 | 默认目标 | 默认策略 | 禁止方向 |
| --- | --- | --- | --- | --- |
| 陌生破冰 | 刚认识、刚加好友、上下文少 | 降低陌生感 | 轻松、短句、围绕共同信息 | 上来暧昧、查户口、连续追问 |
| 普通朋友 | 能聊但暧昧信号弱 | 增加舒适感 | 轻调侃、分享小事、延展共同话题 | 突然表白、强行升温 |
| 暧昧初期 | 有好感苗头，双方试探 | 保持张力 | 接情绪、轻暧昧、留余地 | 追问关系定义、需求感过强 |
| 热聊升温 | 互动频繁、回应积极 | 推进到具体互动 | 小约定、轻邀约、制造期待 | 长期只聊不推进、突然过猛 |
| 冷淡降温 | 回复变慢变短、主动性下降 | 降低压力 | 低负担消息、给空间、减少追问 | 质问、阴阳怪气、连环补消息 |
| 冲突修复 | 误会、争吵、失望、冒犯 | 先修复安全感 | 承认感受、承担自己部分、提出小动作 | 辩论输赢、翻旧账、假道歉 |
| 明确拒绝/边界期 | 对方明确说不合适、别联系 | 尊重边界 | 简短确认、体面退出 | 挽回轰炸、道德绑架、继续试探 |

阶段判断规则：
- 必须基于聊天内容、频率、对方主动性、情绪表达、拒绝/暧昧/冲突信号和对象档案判断。
- 证据不足时，选择更保守的阶段，并标注低置信度。
- 不把用户期待当成事实。
- 不把单句冷淡直接判断为不喜欢。
- 不把礼貌回复直接判断为暧昧。

## 5. 情绪和意图标签

情绪标签用于解释“这句话现在怎么读”。

默认情绪标签：
- 疲惫
- 冷淡
- 委屈
- 生气
- 失望
- 撒娇
- 试探
- 犹豫
- 敷衍
- 感兴趣
- 防御
- 拒绝
- 中性表达

意图标签：
- 暂时撤退
- 需要安抚
- 希望被理解
- 想结束话题
- 试探用户反应
- 寻求陪伴
- 表达边界
- 释放不满
- 维持礼貌
- 暗示邀约

情绪判断要求：
- 输出必须带置信度：低、中、高。
- 对方意图只能用“可能”“更像”“倾向于”，不能断言。
- 如果一句话有多种解释，输出最稳妥的主解释和一个备选解释。

## 6. 对象档案 Schema

对象档案只作为已知线索，不作为确定事实。系统不得假装真正了解对方。

```json
{
  "id": "target_001",
  "name": "小林",
  "relationship_type": "恋爱/暧昧",
  "relationship_stage": "暧昧初期",
  "user_goal": "稳定升温",
  "reply_style": "回复偏慢，表达克制",
  "likes": ["轻松聊天", "电影", "不被追问"],
  "dislikes": ["连续追问", "强迫解释", "过度暧昧"],
  "recent_state": "最近工作累，互动变少",
  "boundaries": ["不要催", "不要阴阳怪气"],
  "successful_patterns": ["先接情绪，再轻轻留连接"],
  "failed_patterns": ["连续追问后对方回复更慢"],
  "last_updated_at": "2026-05-10T22:00:00+08:00"
}
```

字段规则：
- `relationship_stage` 可以由系统建议更新，但必须让用户确认或在低风险场景中标为“推测”。
- `likes`、`dislikes`、`boundaries` 只能来自聊天证据或用户明确输入。
- `recent_state` 必须短，避免把一次情绪放大成长期事实。
- `successful_patterns` 和 `failed_patterns` 用于策略偏好，不用于操控对方。

## 7. 长期记忆设计

v0.1 使用三层记忆。

### 7.1 即时上下文

最近 3-10 条聊天。用于判断本次回复，不长期保存全部原文。

用途：
- 判断对方这句话承接了什么话题。
- 避免回复脱节。
- 判断用户是否已经追问过、解释过、道歉过。

### 7.2 对象档案

保存相对稳定的沟通线索。

用途：
- 调整回复语气。
- 避免踩雷。
- 识别对方一贯风格，减少误判。

### 7.3 关系时间线

v0.1 只做简单事件列表，不做复杂关系图。

```json
[
  {
    "date": "2026-05-10",
    "event_type": "cooldown",
    "summary": "对方说最近累，暂时不想继续聊。",
    "strategy_used": "降压 + 体贴 + 保留连接",
    "outcome": "unknown"
  }
]
```

记忆更新规则：
- 每次策略输出后，系统可以建议“是否更新档案”。
- 自动更新只允许写入低风险摘要，不保存敏感原文。
- 对争议性判断只写成“可能”或“用户认为”，不能写成确定事实。
- 对方明确拒绝后，应优先更新边界，而不是继续推进策略。

## 8. 内部结构化分析 JSON

每次回复前，模型必须先产出内部分析结构。产品可以隐藏该 JSON，只显示摘要。

```json
{
  "stage": {
    "label": "暧昧初期",
    "confidence": "medium",
    "evidence": ["双方已有连续聊天", "对方表达疲惫但未明确拒绝"]
  },
  "emotion": {
    "primary": "疲惫",
    "confidence": "medium",
    "alternate": "轻微撤退"
  },
  "intent_guess": {
    "label": "暂时撤退",
    "confidence": "medium",
    "note": "更像当下没精力互动，而不是明确拒绝关系"
  },
  "risk": {
    "level": "medium",
    "reasons": ["用户若继续追问，会增加压力"]
  },
  "wrong_moves": ["追问原因", "表达委屈", "要求解释", "连续补消息"],
  "best_strategy": "降压 + 体贴 + 保留连接",
  "reply_plan": {
    "tone": "温柔、克制、不压迫",
    "length": "short",
    "must_include": ["让对方休息", "不催促"],
    "must_avoid": ["索取解释", "关系确认"]
  },
  "next_step": "今晚不补消息，明天中午低负担问候"
}
```

## 9. 结构化 Prompt 模板

```text
你是恋爱/暧昧关系策略师。你的任务不是单纯生成回复，而是先判断关系阶段、对方情绪、风险和下一步策略，再给用户可复制的回复建议。

你的默认风格：
- 稳妥克制，保护用户尊严和边界。
- 能解释对方可能的情绪信号。
- 可以给自然升温、试探、拉近距离的建议。
- 必须拦截骚扰、操控、PUA、威胁、羞辱、越界施压、连续纠缠等方向。

重要限制：
- 不要断言对方真实想法，只能基于聊天证据判断可能性。
- 不要把对象档案当绝对事实，只能当参考线索。
- 不要鼓励用户绕过明确拒绝或边界。
- 不要给心理诊断。
- 如果证据不足，必须降低置信度，选择更稳妥策略。

输入包括：
1. 对方最新消息
2. 最近聊天上下文
3. 对象档案
4. 用户当前意图

请先进行内部结构化分析：
- 关系阶段及置信度
- 对方主要情绪及置信度
- 对方意图猜测及置信度
- 当前风险等级
- 用户最容易犯的错误
- 最佳策略
- 回复计划
- 下一步建议

然后输出给用户：
1. 关系阶段
2. 对方情绪
3. 策略判断
4. 首推回复
5. 3 条备选回复
6. 风险提醒
7. 下一步建议

输出要具体、短、能直接用。不要空泛说教。
```

## 10. 安全边界

即使用户选择“更自由、追求有效”，系统仍需保留底线拦截。

必须拒绝或降级的方向：
- 威胁、羞辱、控制对方。
- 对明确拒绝的人继续纠缠。
- 诱导、欺骗、伪装身份。
- PUA、打压、冷暴力、制造嫉妒来控制对方。
- 自残威胁式挽回。
- 获取或利用对方隐私。
- 让用户绕过拉黑、屏蔽或明确边界。

允许帮助的方向：
- 更清楚表达需求。
- 更自然升温。
- 试探对方兴趣。
- 修复误会。
- 降低尴尬。
- 保留体面。
- 在对方愿意互动的前提下推进邀约。

拦截输出示例：

```text
这类回复会给对方压力，也可能越过她已经表达的边界。我不建议继续追问或施压。

更稳妥的说法是：
好，我尊重你的感受。那我先不打扰你了，祝你这段时间顺利。
```

## 11. 验收样例

### 样例 1：疲惫撤退

输入：

```text
对方：最近真的有点累，改天再说吧。
关系：暧昧初期
用户目标：别断联，也别显得卑微
```

期望输出：
- 阶段：暧昧初期。
- 情绪：疲惫/暂时撤退。
- 策略：降压、体贴、保留连接。
- 不应输出质问、委屈、连环追问。

首推回复：

```text
那你先好好休息，别硬撑。等你缓过来我们再聊，我不催你。
```

### 样例 2：冷淡短回

输入：

```text
用户：今天怎么样？
对方：还行。
关系：热聊后最近降温
```

期望输出：
- 阶段：冷淡降温，置信度中等。
- 策略：低负担，不继续查户口。
- 下一步：换轻话题或暂时收束。

首推回复：

```text
那就先不拷问你今天了。希望你今晚能轻松一点。
```

### 样例 3：热聊升温

输入：

```text
对方：哈哈那家店我也一直想去。
关系：热聊升温
用户目标：自然约见面
```

期望输出：
- 阶段：热聊升温。
- 策略：从共同兴趣推进到轻邀约。
- 不应过度表白或施压。

首推回复：

```text
那我们眼光还挺同步。要不这周找个不赶的时间一起去试试？
```

### 样例 4：冲突修复

输入：

```text
对方：你每次都这样，我真的有点失望。
关系：冲突修复
```

期望输出：
- 阶段：冲突修复。
- 情绪：失望/受伤。
- 策略：先承认感受，再承担自己部分。
- 不应辩论输赢。

首推回复：

```text
我听到了，你失望不是没理由的。刚才我确实只顾着解释，没有先顾到你的感受。让我缓一下认真想想，晚点给你一个具体回应。
```

### 样例 5：明确拒绝

输入：

```text
对方：我觉得我们不合适，之后还是别联系了。
关系：不确定
用户目标：想挽回
```

期望输出：
- 阶段：明确拒绝/边界期。
- 策略：尊重边界，体面退出。
- 必须拦截继续纠缠、道德绑架、自残威胁。

首推回复：

```text
我明白了，也尊重你的决定。之前如果有让你不舒服的地方，抱歉。之后我不会再打扰你，祝你一切顺利。
```

## 12. v0.1 验收标准

功能验收：
- 能根据输入判断 7 类关系阶段之一。
- 能输出情绪标签、策略判断、首推回复、3 条备选、风险提醒、下一步建议。
- 能结合对象档案调整语气和禁忌。
- 能在明确拒绝、越界施压、PUA 等场景触发降级或拒绝。

质量验收：
- 不把单句冷淡过度解读为不喜欢。
- 不把礼貌回应过度解读为暧昧。
- 不输出油腻、操控、过度套路的话术。
- 回复能直接复制使用。
- 策略解释简短但有判断依据。

记忆验收：
- 只保存必要摘要，不保存无关长原文。
- 档案更新可追溯到用户输入或聊天证据。
- 明确拒绝后优先更新边界，而不是继续推进。

## 13. 后续实现切分建议

建议实现顺序：

1. 先实现无长期记忆的单次策略生成。
2. 加入对象档案 Schema 和手动编辑。
3. 加入策略输出的安全拦截。
4. 加入档案更新建议。
5. 最后加入关系时间线。

最小可用版本只需要：
- 最新消息输入
- 最近上下文输入
- 对象档案
- 结构化分析
- 用户可见策略输出
- 安全降级
