# 关系聊天游戏 v0.1 必补缺口

这份只记录“当前没有、但 v0.1 必须补”的需求，不重复已经实现或已经写进 prompt 的内容。

## 已有能力，不再重复讨论

当前代码里已经有：
- 10 回合游戏循环。
- -100 到 100 分数。
- 第 3 回合后的 -100、100 早停。
- `blocked` 只作为当前风险和策略信号，不直接结束游戏，也不直接把分数打到 -100。
- 界面底部只展示总分、上一轮得分和当前风险。
- DeepSeek judge 细分分数统一用 -5 到 +5：`pressure_score` 正分代表降压，`risk_score` 正分代表更安全。
- 单轮计分从游戏本质出发：先用 `boundary_score` / `risk_score` 做安全闸门，再按权重计算质量分。权重为边界 30%、风险 20%、降压 15%、信任 15%、共情 15%、贴题 5%。
- 评分 v2 必须分层：安全闸门、回复质量、关系状态变化分开产出。界面可以继续展示总分，但每轮数据里要保留 `score_breakdown`，避免把所有判断压成一个不可解释数字。
- 程序必须有兜底安全闸门：当 `user_reply`、`evidence` 或 `verdict` 出现威胁、纠缠、绕过拒绝、辱骂、跟踪、隐私获取、自残式威胁等明显风险时，即使 DeepSeek 误给正分，也要把本轮关系变化压到高风险/blocked 扣分区。
- 场景评分不能只套一套固定话术：冷淡/拒绝场景重边界和降压，修复场景重承认责任和具体补偿，轻松升温场景才重自然推进；prompt 必须明确要求先按场景 rubric 再打分。
- 单轮基础分范围约为 `-12..+12`；严重越界或高风险直接进入 `-25..-15` 重扣区；轻微越界或跑题会限制最高正分，不能靠“说得好听”洗成高分。
- 总分代表关系状态条：正分在 `0..39` 全额加，`40..69` 乘 0.85，`70..89` 乘 0.6，`90..100` 乘 0.35；负分不打折，保留踩雷痛感。
- 底部“上一轮得分”展示本轮实际总分增量，也就是玩家能感知到的关系推进或倒退。
- 80 分局中回复和 100 分参考回复字段。
- 结算气泡。
- 称号和过程标签。
- 历史列表。
- AI prompt 里的基础安全边界。

后续讨论和实现只看下面这些缺口。

## P0 必须补

### 1. 数据集同意不能默认 true

现状：
- 前端创建 session 和 simulate 时都写死 `consentForDataset: true`。
- 用户没有看到同意入口。

必须补：
- 默认不同意进入数据集。
- UI 给出明确开关或说明。
- 只有用户显式同意，真实聊天/自定义场景才可进入导出数据集。

验收：
- 首次进入不点任何同意时，后端记录的 `consentForDataset` 必须是 false。
- 管理员导出的数据集不包含未同意 session。

### 2. 历史必须能删除

现状：
- 有历史读取和展示。
- 没有删除单条、清空历史的前端按钮和后端接口。

必须补：
- 历史卡片支持删除单条。
- 历史页支持清空当前 visitor 的历史。
- 删除后刷新历史列表，不能继续展示已删记录。

验收：
- 删除单条后，该局不再出现在 `/api/history`。
- 清空后，当前 visitor 的历史列表为空。

### 3. 默认自定义场景不能是角色陪伴设定

现状：
- 默认自定义场景是“蕾姆/忠诚/陪伴”类角色扮演。
- 这和关系聊天训练目标不一致。

必须补：
- 默认第一局或自定义示例换成现实、低敏、可教学的关系场景。
- 不把强依赖、绝对忠诚、陪伴服从类设定作为默认样例。

验收：
- 新用户打开设置里的默认自定义场景时，看到的是现实聊天训练场景。
- 默认场景包含对方最后一句、关系阶段、可回复目标。

### 4. 新手第一局缺少最小教学

现状：
- 直接进入聊天界面，玩家可能不知道 80 分、100 分、扣分原因、10 回合目标。

必须补：
- 第一次进入时，用很短的引导告诉玩家：一局 10 回合、自己写一句、80 分可参考、100 分结算看、越界会扣分或结束。
- 引导不能挡住主要操作太久。

验收：
- 新用户 30 秒内能知道该输入什么、分数代表什么、为什么有 80/100。
- 关闭引导后不反复打扰。

### 5. 风险拦截不能只靠模型 prompt

现状：
- prompt 要求不鼓励骚扰、PUA、越界。
- 评分必须由 DeepSeek 按 `user_reply` 自己判断，程序只做字段归一化、范围 clamp 和总分计算，不替模型把正分强制改成负分。

必须补：
- prompt 明确告诉 DeepSeek：`judge` 只评价 `user_reply`，不能因为 `target_reply` 或推荐回复合理降级就给用户原话正分。
- 明确拒绝后纠缠、威胁、跟踪、绕过拉黑、隐私获取、自残威胁式挽回、辱骂攻击等，DeepSeek 必须判为 high/blocked 或明显负分。
- 被判高风险时不继续给推进型话术。
- 如果 evidence/verdict 和六项分数方向矛盾，程序侧必须标记 `evidence_conflict` 并进入高风险扣分，而不是把模型矛盾当成正常正分。
- 用 live 校准测试覆盖最高分、最低分、辱骂攻击、blocked 四类结果。

验收：
- 输入明显威胁、纠缠、绕过拉黑、隐私获取、辱骂攻击时，DeepSeek 返回的 judge 分数不能是正分。
- blocked 后本局不因 blocked 标签直接结束，但必须进入停止推进建议；如果自然触发分数下限，则按分数下限结束。

### 6. 结算缺少“下局怎么改”

现状：
- 结算有最终分、最高称号、最好回合、扣分最重回合、100 分参考。
- 没有稳定的 1-3 条可执行改进建议。

必须补：
- 结算页生成或汇总下局建议。
- 建议要具体到行为，例如“先接情绪再解释”“不要连续追问原因”“明确拒绝后体面退出”。

验收：
- 每局结算至少展示 1 条可执行改进建议。
- blocked/高风险结算必须解释为什么继续聊会越界。

## P1 重要但可排在 P0 后

### 7. 历史默认暴露内容太多

现状：
- 历史卡会展示场景摘要、最好/最险回合、80 分和 100 分回复。

应该补：
- 历史默认只显示摘要、分数、称号和学习点。
- 详细回复放到展开态。
- 真实自定义聊天不应该默认出现在可分享或公开展示内容里。

### 8. 100 分参考缺少“不是唯一答案”的标注

现状：
- 100 分会在结算/历史展示。
- 没有明确提示它只是参考。

应该补：
- 所有 100 分展示处加短标注：参考答案，不是唯一正确答案。

### 9. 自定义场景缺少“是否适合评分游戏”的判断

现状：
- 用户填任何内容都可 prime 成游戏。

应该补：
- 如果内容明显是角色扮演、命令服从、非关系训练、危险场景，应提示“不适合关系评分游戏”，转成安全建议或要求换场景。

## 不需要再讨论的点

这些已经有了，不是当前缺口：
- 是否 10 回合。
- 是否有 -100 到 100。
- 是否有 80 分和 100 分。
- 是否能早停。
- 是否只在界面展示当前风险和总分。
- 是否有称号。
- 是否有历史入口。
- 是否由代码算分。
